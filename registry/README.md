# Маркет модулей

Конструктор бота показывает модули в трёх разделах:

| Раздел | Откуда | Что гарантирует |
|---|---|---|
| Официальные | модули из этого репозитория | собираются вместе с ядром, покрыты тестами |
| Проверенные | `registry/verified/*.json` | код прочитан мейнтейнерами на конкретной версии |
| Свои | файл `tors-module.json`, который человек открыл в конструкторе | ничего — его модуль, его ответственность |

`index.json` — то, что читает конструктор. Он генерируется, руками не правится:

```sh
go run ./cmd/tors market-index --verified registry/verified -o registry/index.json
```

## Описание модуля

Модуль попадает в конструктор, если реализует `market.Describer`:

```go
func (*App) Market() market.Info {
	return market.Info{
		Name:     "Кошелёк",
		Summary:  "Баланс в звёздах и оплата с баланса.",
		Category: "feature",
		Requires: []string{"billing", "users"},
		Config:   []market.Field{{Key: "bonus", Title: "Бонус за пополнение, %", Type: "number"}},
	}
}
```

Экраны, данные, действия и события модуль описывает через `ui.Provider` (`UI() ui.Contribution`), и они же попадают в описание: конструктор проверяет по ним экраны ещё до сборки. Стартовые экраны (`Contribution.Screens`) ложатся на холст, когда модуль добавляют.

Файл описания собирает сам бинарь, в который вкомпилирован модуль:

```sh
tors build --config my-bot.json -o tors   # сборка с вашим модулем
./tors describe --package github.com/you/tors-wallet -o tors-module.json
```

`tors-module.json` можно сразу открыть в конструкторе в разделе «Свои» — модуль появится в списке, а при экспорте попадёт в раздел `build` конфигурации с точной версией из `go.mod`.

## Как модуль становится проверенным

1. Автор публикует модуль как Go-модуль с тегом версии (`v1.2.0`). Ветки и `latest` не принимаются: проверяется конкретный код.
2. Открывает pull request, который добавляет `registry/verified/<автор>-<модуль>.json` — вывод `tors describe` для этой версии.
3. Мейнтейнеры читают код этой версии и проверяют:
   - ID модулей принадлежат автору и не выдают себя за официальные (`market-index` это тоже отклоняет);
   - модуль пишет только в свою схему PostgreSQL и публикует только свои события;
   - секреты берутся из конфигурации (`{env.…}`), не зашиты в код и не уходят на сторонние адреса;
   - внешние запросы идут только туда, куда модуль обещает в описании;
   - нет `init()` с побочными эффектами кроме `tors.RegisterModule`;
   - тесты проходят (`go test ./...`), зависимости закреплены в `go.sum`.
4. После слияния `index.json` пересобирается, и модуль виден всем в разделе «Проверенные».

Новая версия — новый pull request с обновлённым файлом: одобрение не переносится на код, которого никто не читал.

Проверка — это чтение кода людьми, а не песочница. Модуль работает в одном процессе с ботом; в продакшене изоляцию данных даёт отдельная роль PostgreSQL на модуль (см. `docs/PLAN.md`).
