# TORS

Модульный Telegram-бот для продажи VPN-подписок на Go. Панели — Remnawave 3.x (следующая — 3x-UI), оплата — Telegram Stars.
Архитектура «микроядро + модули» по образцу Caddy v2: ядро только загружает модули и управляет их жизнью, всё остальное —
модули, в том числе сторонние.

Бота собирают в конструкторе: пустой холст → модули из маркета → свои экраны → `bot.json` → `tors build` → запуск.

## Как собрать бота

1. **Конструктор.** Откройте `web/ui-editor` (как запустить — в его README) и добавьте модули: «Подписки» сами подтянут
   оплату и тарифы, останется выбрать панель. Их экраны лягут на холст. Нарисуйте свой экран-меню и свяжите кнопки
   с экранами модулей. Внизу слева — ошибки, «Проверить» — чат-симулятор.
2. **Экспорт.** «Экспорт → Скачать bot.json». В файле — список модулей для сборки, настройки и все экраны.
3. **Сборка и запуск:**

   ```sh
   go run ./cmd/tors build --config bot.json --replace . -o bot   # бинарь ровно с модулями бота
   export BOT_TOKEN=… DATABASE_URL=postgres://… REMNAWAVE_TOKEN=…
   ./bot run --config bot.json
   ```

   Или в Docker вместе с PostgreSQL: положите `bot.json` в `deploy/`, заполните `deploy/bot.env` по примеру и выполните
   `docker compose -f deploy/compose.yaml up -d --build`.

## Модули

| Модуль | Что делает |
|---|---|
| `telegram` | Показывает экраны, обрабатывает кнопки, ввод текста и события; состояние кнопок хранится на сервере |
| `users` | Пользователи и их язык |
| `catalog` | Тарифы из конфигурации |
| `billing` + `billing.gateways.stars` | Заказы и оплата звёздами; оплата подтверждается один раз и публикуется как надёжное событие |
| `subscriptions` | Несколько подписок на человека: выдача и продление после оплаты, ссылка, переименование, напоминания |
| `panels` + `panels.providers.remnawave` / `fake` | Панели по именам; Remnawave через официальный SDK v3.4.4, `fake` — для проверки |
| `trial`, `support` | Пробный период один раз на человека; контакт поддержки |
| `database`, `jobs`, `kv`, `http`, `ui` | PostgreSQL со схемой на модуль, очередь задач и события с повторами, состояние диалогов, HTTP для вебхуков, реестр экранов |

Сторонний модуль — обычный Go-пакет с `tors.RegisterModule` и методом `Market()`; конструктор принимает его описание
(`tors describe`) в разделе «Свои», а проверенные попадают в общий маркет — см. [`registry/README.md`](registry/README.md).

## Устройство репозитория

| Путь | Что там |
|---|---|
| корень (`tors`) | ядро: реестр модулей, жизненный цикл, конфигурация, события — только стандартная библиотека |
| `cmd/` | командная строка: `run`, `validate`, `build`, `describe`, `market-index`, … |
| `theme/` | формат экранов, проверки, шаблоны и отрисовка — общий код бота и конструктора (в конструкторе через WebAssembly) |
| `market/` | описание модулей для конструктора |
| `modules/` | модули; `modules/standard` подключает их все |
| `registry/` | индекс маркета и проверенные сторонние модули |
| `web/ui-editor/` | конструктор бота |
| `deploy/` | Dockerfile бота и конструктора, `compose.yaml` |
| `docs/PLAN.md` | архитектура, решения и дорожная карта |

## Разработка

Нужны Go 1.27+, PostgreSQL для интеграционных тестов и Node.js 22+ для конструктора.

```sh
export TORS_TEST_DSN=postgres://postgres@127.0.0.1:5432/postgres?sslmode=disable
go test ./...        # без TORS_TEST_DSN тесты с базой пропускаются
go run ./cmd/tors market-index --verified registry/verified -o registry/index.json   # после изменения описаний модулей
```

Тесты Telegram идут против поддельного Bot API (`internal/tgtest`), полный сценарий покупки — в `modules/standard`.
